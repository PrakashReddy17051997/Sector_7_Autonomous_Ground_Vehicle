## 1. Start align - put the rover down facing ANY direction

`LocalLocalizer::alignSearch` + `RouteFollow::start`.

The leg map (LocalPath.h) is a 10 cm likelihood grid G (4 bit per cell) of the taught walls. For a scan
with points p_i (rover frame) and a candidate pose (x, y, th) the score is

    S(x, y, th) = 1/(15 n) * sum_i G( R(th) p_i + [x y] )        R(th) = [cos -sin; sin cos]

- coarse: th = -180..176 deg in 4 deg (90 values) x position +-0.6 m in 0.2 m (7 x 7) = 4410 poses,
  each ~60 points -> 265 000 grid look-ups. Host 1-5 ms; on the ESP32 ~0.1-0.3 s, once.
- the winner is refined (5 cm / 2 deg, then 2 cm / 1 deg).
- **ambiguity check**: second = best score at least 30 deg away from the winner (e.g. a straight
  corridor seen from the other end). Accepted only if best >= 0.45 AND best - second >= 0.06.
- then `routeYaw = ref + th` (offset `_off = ref + th - gyroYaw`), the localizer pose is set, and the
  route starts in TURN: soft gyro-closed pivot (0.35) to the leg direction, then DRIVE.
- not sure -> old rule; page says "start not clear (score/2nd): turn rover along the path".

Host test (`tools/v3_test/align_test.cpp`): real start scans of log_026/027/028/029 rotated to all 90
orientations: **360 of 360 correct**, best 0.63-0.73 vs second ~0.41.
Page (Dev): `start.align` = degrees off, score, 2nd.

## 2. Landmark legs - the batchmate's Open Sea method, as a table

`LineFeat.h` (line extraction) + `LandmarkLeg.*` (phases) + `LandmarkRoute.h` (tables).

### 2.1 A robust straight line from 90 LiDAR points
Sector of +-45 deg around the expected side. RANSAC over ALL point pairs (a sector has <= 30 points ->
<= 435 pairs, cheap): the line through the pair with the most inliers, where a point is an inlier if

    |n . p - d| <= tol0 + tolK * r      (0.05 + 0.025 r)

(a 4 deg bin smears a point sideways by up to r * sin 2 deg = 0.035 r). Then a total-least-squares refit:

    centroid c, covariance Sxx, Syy, Sxy
    line direction  th = 1/2 atan2(2 Sxy, Sxx - Syy),   normal n = th + 90 deg
    rms = sqrt(lambda_min / m),  lambda_min = (tr - sqrt(tr^2 - 4 det)) / 2

Line form: `cos(foot) x + sin(foot) y = d`. foot = direction to the closest point of the line
(+90 left wall, -90 right, 0 ahead, 180 behind). Trees, poles, people: too few inliers -> ignored.

### 2.2 What a line tells us
Rover turns left by e -> every foot angle drops by e. So the course the line stands for (route frame):

    lineYaw = routeYaw - (footExp - foot)

On course `lineYaw = ref + lineOff`. **lineOff** (measured on log_027): behind -9.5, store front -9.6,
ahead -9.9 deg - the three walls are square to each other; the 9.6 deg is our crab (nose left of the
track). So the landmark legs steer in the same "nose heading" frame as `ref`, without the crab term.
A line counts only if `|lineYaw - (ref + lineOff)| <= para` (8 deg): a diagonal bike rack does not.

### 2.3 Heading anchor = complementary filter (gyro + landmark)
    _off(k+1) = _off(k) + g * wrap(ref + lineOff - lineYaw),   g = 0.05..0.10 per scan, max 0.5 deg/scan

The gyro is smooth but drifts (~2 deg/min); the line has scan noise but no drift. At 4 Hz the time
constant is 1/(4 g) = 2.5 s (g = 0.10) -> noise averaged over ~10 scans, drift removed for good.

### 2.4 Side PID (store front at 6.75 m) - cascade
Outer loop: distance -> heading offset. Inner loop: the existing rolling heading PD (hKp/hKd).

    e = d - dRef                      (+ = too far from the line)
    turn = kp e + ki int(e dt) + kd de/dt,   |turn| <= 8 deg,  anti-windup (integrate only unsaturated)
    yawDes = (lineYaw - lineOff) + side * turn        side = +1 for a left line

Lateral kinematics: de/dt = v sin(dpsi) ~ v dpsi. With a fast inner loop and dpsi = -(kp e + kd de/dt) * pi/180:

    de/dt * (1 + v kd k) = - v kp k e,   k = pi/180
    -> first order, tau = (1 + v kd k) / (v kp k)

v = 0.25 m/s, kp = 10, kd = 20: tau = 1.09 / 0.0436 = **25 s**; max approach speed v sin 8 deg = 3.5 cm/s.
Slow and smooth on purpose (worn gears, line found on only 13-50 % of scans). ki = 1.5 removes a constant
rest (crab not fully in lineOff, battery). kd mostly helps against the inner-loop lag.
**Gaps**: between line hits the last offset to ref is held and fades out over 2 s (the replay showed a
+-4 deg flip-flop without this).

### 2.5 Stop at the end wall, crowd rule (v10)
Line ahead, >= 2 m long, parallel check, in 3 of the last 5 scans, and **fixed in space**:
for a wall `d + s = const` while driving towards it (s = metres driven). People walking towards the
rover change d + s by their own speed; we accept a spread < 0.4 m. Stop at d <= 3.0 m (taught leg end:
3.07 m in log_027). Lines are ignored while tilted (pitch > 3.5 deg off the start level: ramp at 0-6 m
and the step at ~28 m).

## 14. K-turn instead of turning on the spot (12.11. evening, tested in tools/sim_v3)

logs 030-034 (rover 7, 7900 samples) sorted by wheel direction: wheels OPPOSITE (every pivot, also "rolling"
pivots): median 0 deg/s; both wheels FORWARD (curve): 16.7 deg/s per unit w; both BACKWARD: 31 deg/s per unit w.
So every turn is now a K-turn (`RouteFollow kTurn = true`, tactic `TK_KTURN`): backward curve (outer wheel -0.50,
inner -0.05) and forward curve (outer +0.50, inner +0.05) alternate - the body rotates the same way in both -
until the heading is reached. Pieces end when the LiDAR / ultrasonics see no room or the rover is 0.2 m off where
the turn began (it stays within ~0.5 m). Used by the start turn, every corner and the obstacle detour.
